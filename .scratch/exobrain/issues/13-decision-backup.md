# 13 决策：备份与数据安全

Type: grilling
Status: claimed
Blocked by: 06, 09

## Question

外脑的数据（笔记原文、向量索引、配置）是整个系统最值钱的资产。与本人对话确定：

1. **备份对象**：哪些数据必须备份（Markdown/笔记库、数据库、向量索引能否直接重建）；
2. **备份目标**：阿里云对象存储（OSS，同地域内网传输免费/便宜）、私有 Git 仓库（Gitee/GitHub，服务器在国内的推送连通性）、或两者结合；
3. **备份方式与频率**：定时脚本 + 压缩打包 + 保留策略（保留近 7 天 + 每月一份之类）；
4. **恢复演练**：如何验证备份可用（一次完整恢复的步骤说明）；
5. **密钥安全**：API 令牌、访问密钥不进备份明文、不进 Git 的措施。

产出：备份方案决策记录 + 可直接部署的备份脚本思路。

## Answer

2026-09-06 与本人对话定稿。方案全文与恢复演练步骤见工件 [prototypes/backup-plan.md](../prototypes/backup-plan.md)。

1. **备份对象**：只有 vault 笔记库需要真正备份（不可重建）；SQLite 索引/jobs 不备份（`ybrain reindex` 全量重建，bge-m3 嵌入免费、几分钟完成，队列可从收件箱扫描重建）；headscale 配置不备份（重建控制面约 15 分钟）；
2. **备份目标**：**Gitee 私有仓库**（深圳服务器推国内线路稳定）；服务器每次提炼 commit 后自动 push（失败告警不阻塞），Mac 端 Obsidian Git 插件每 10 分钟 pull；服务器/Mac/Gitee 三份副本；服务器用仅对该仓库有写权限的部署密钥；
3. **密钥安全**：`.env` 不进 Git、不进备份；本人在密码管理器留存密钥记录，所有密钥平台侧可重新生成；
4. **恢复演练**：七步清单（装 Docker/swap → 重建 headscale 组网 → clone fork 与 vault → 重填 .env → 起容器 → reindex → 验证），作为票据 14 的一条验收项（干净机器走完全流程并能检索到旧笔记）；
5. **日常检查**：周复盘会话顺带报告最近推送时间与 dead 任务数；本人每月瞄一眼 Gitee 确认推送持续。
