# 05 调研：三条捕获渠道的实现方式

Type: research
Status: resolved
Blocked by: 无

## Question

调研 MVP 三条捕获渠道的具体实现路径，为捕获方案决策（08）提供事实依据。服务器无域名、无微信公众号平台，手机是 Android。

**渠道一：电脑浏览器网页剪藏**

- 浏览器扩展 vs 书签小工具（Bookmarklet）的取舍；
- 网页正文提取方案：Mozilla Readability、Python 的 trafilatura/readability-lxml 等，中文网页（含微信公众号文章页）的提取效果；
- 剪藏时发送给服务器的数据形态（网址 + 正文，还是浏览器端提取后发正文）。

**渠道二：Android 手机随手速记**

- Android 系统分享菜单接入 HTTP 请求的成熟工具：HTTP Shortcuts、Tasker、Easydict 类工具等，哪个能在系统分享面板中直接接收"文本/链接"并 POST 到服务器；
- 纯文字速记、链接分享两种场景的操作步数对比；
- 是否有开源的轻量 Android 客户端值得直接用或二次开发。

**渠道三：微信生态内容**

- 公众号文章：在微信内"复制链接"后经 Android 分享工具发送的完整路径是否顺畅；有无更短路径（如微信内直接分享到第三方工具的可行性）；
- 微信读书：划线笔记/书摘是否有可用的导出方式（官方导出、非官方接口、定时同步），各自的封号风险与维护成本；
- 明确哪些路径稳定可用、哪些属于灰色 hack 不建议依赖。

产出：每条渠道的推荐实现、操作步数、开发工作量（自研部分大致是什么）、风险点。注意中文写作，技术缩写首次出现写全称。

## Answer

研究报告全文：[research/05-capture-channels.md](../research/05-capture-channels.md)

结论（供 08 决策使用）：

- **网页剪藏**：自研 Manifest V3 浏览器扩展为主力——浏览器端用 Mozilla Readability + Turndown 提取 Markdown 全文后 POST 到服务器（1 步操作，约 2–4 人日）；书签小工具零安装兜底发网址；
- **正文提取放浏览器端**：服务器端 trafilatura 提取质量最高但只做普通站点兜底；公众号文章有机房 IP 风控和图链失效问题，服务器直抓不稳定；
- **Android 速记**：HTTP Shortcuts（MIT 开源、F-Droid 可装）原生支持分享菜单接收文本、可自定义 Bearer 鉴权令牌；链接分享 3 步、桌面小部件纯速记 3 步，App 端零代码，服务器接口约 1 人日；现成客户端 Moe Memos 体验最完整但绑定 Memos 接口；
- **微信公众号**：微信内不开放系统分享面板，稳定路径是"在浏览器打开"后走浏览器/Android 渠道，不做服务器抓取公众号；
- **微信读书**：2026 年 5 月官方已开放 API Key（wrk- 开头）可导出划线/想法，推荐服务器定时同步（已毕业为独立票据 15）；Cookie 模拟类插件在 2026 年封号潮中被官方点名，不押注；
- **通道辨向**：企业微信群机器人、Server 酱、PushPlus 均为单向推送不能接收；唯一官方双向通道是企业微信自建应用回调（个人可免费注册，WebSocket 长连接模式免公网回调地址）——可作为微信内速记的可选增强，在 08 中决策。
