# 11 设计：检索增强问答管线

Type: prototype
Status: resolved
Blocked by: 06, 07

## Question

**按票据 06 修订（fork 二开）与票据 07 选型调整（2026-09-06）：检索以 ybrain 内的原生工具实现（TypeScript/Bun），嵌入用 SiliconFlow 免费 bge-m3、重排用免费 bge-reranker-v2-m3，答案合成由代理本体完成。** 设计知识库检索能力并产出可运行的最小原型：

1. **索引构建**：新内容入库（或代理处理后文件变更）后何时分块、向量化；中文文本的分块策略（按段落/固定长度/语义边界，重叠长度）；sqlite-vec 在 Bun 下的集成方式（sqlite-vec npm 包 + better-sqlite3/bun:sqlite）；
2. **检索工具（原生）**：`search_knowledge` 工具的入参/出参契约——向量检索取多少条、是否按笔记合并、重排启用策略；返回含笔记标题、文件路径、原始链接、匹配片段，供代理引用出处；
3. **代理侧问答约定**：ybrain 的系统提示/指令——只依据检索结果与笔记原文回答、给出处引用、资料不足明说"不知道"；
4. **多轮对话**：由 opencode 会话天然承担，不做独立对话状态；
5. **产出工件**：检索原型（Bun/TS：对几篇示例文本完成"SiliconFlow 嵌入→sqlite-vec 检索→重排"并打印结果）+ 工具描述草稿 + 系统指令草稿，供本人实际提问感受质量。

## Answer

2026-09-06 原型已真实跑通（SiliconFlow 实测，非 mock）。

**工件**：
- 可运行原型：[prototypes/rag-prototype/search_demo.py](../prototypes/rag-prototype/search_demo.py)（Python 零依赖，生产 Bun/TS 照搬分块与检索逻辑）；
- 工具契约与代理指令：[prototypes/rag-tools-and-prompt.md](../prototypes/rag-tools-and-prompt.md)（四个原生工具签名 + AGENTS.md 指令草稿 + 工程参数表）。

**实测结果**（4 篇示例笔记 → 9 分块 → bge-m3/1024 维 → 粗取 top8 → 重排 top3）：

| 提问 | 结果 | 重排最高分 |
| --- | --- | --- |
| 外脑怎么记住并找回东西 | ✅ 精准命中剪藏原文与提炼笔记 | 0.981 |
| 威科夫 spring 跌破支撑意味着什么 | ✅ 精准命中书摘；粗取第 2 的噪声（0.49 余弦）被重排压到 0.048，**重排纠偏价值验证** | 0.896 |
| 归档后还能搜到吗 | ◑ 部分命中（示例库尚无 4-Archive 笔记） | 0.302 |
| 手机上怎么快速记想法 | ✗ 库中无对应内容（示例原文截断所致），重排分全部 ≤0.09 → **阈值机制生效，代理将答"资料不足"而非硬编** | 0.023 |

**原型暴露并已定论的工程点**：
1. **索引以 note_id 对账**：笔记从收件箱移动到 PARA 后，旧路径的 chunks 必须先删后插（原型中同一笔记两态被重复索引）；
2. **索引范围**：提炼区（`## 原文` 之前）入向量库，原文区不入、需要时 get_note 读全文；
3. **可靠性阈值**：rerank_score < 0.1 视为无可靠资料，代理明说"不知道"并建议捕获什么；
4. 分块参数：标题切段 + 中文句末标点贪心聚合，目标 400 字/上限 600/重叠约 50 字；
5. 多轮对话由 opencode 会话天然承担，ybrain 不做对话状态。

**对票据 12 的输入**：提炼指令草稿（含 PARA 归类规则、书摘拆卡规则、批注区留白）已在工件中，12 在此基础上补任务队列契约与状态机。
