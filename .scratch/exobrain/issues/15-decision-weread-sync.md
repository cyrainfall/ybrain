# 15 决策：微信读书划线同步是否纳入 MVP

Type: grilling
Status: claimed
Blocked by: 06

## Question

调研（05）发现：微信读书已于 2026 年 5 月官方开放 API Key（wrk- 开头），可导出划线与想法；非官方 Cookie 模拟方式在 2026 年封号潮中被官方点名，不可押注。与本人对话确定：

1. **是否纳入 MVP**：微信读书书摘/划线同步是首发能力还是 MVP 之后；
2. **同步形态**：若做，服务器定时拉取（频率、增量策略）后按普通笔记进入收件箱，走与剪藏相同的提炼流程；
3. **密钥与账号**：API Key 的申请位置与存放方式（同 07 的密钥管理原则）；
4. **边界**：只同步划线/想法，不做书架管理、不做阅读进度。

注：本票据由雾区"微信读书划线/笔记同步"毕业而来，事实依据见 [research/05-capture-channels.md](../research/05-capture-channels.md)。

## Answer

2026-09-06 与本人对话定稿。

1. **不纳入 MVP**：MVP 捕获渠道为浏览器扩展 + Android HTTP Shortcuts 两条；微信读书同步作为 **MVP 之后第一个增量**（接口契约与数据模型 type: weread 已预留，构建时不返工）；
2. **实现方式（将来）**：官方 API Key（`wrk-` 开头，https://weread.qq.com/r/weread-skills 扫码获取），ybrain 定时任务**每天凌晨增量拉取一次**（按划线时间戳游标只取新增），按"书+日期"聚合成 `type: weread` 笔记落收件箱，走票据 12 标准提炼流程（含拆知识卡片）；
3. **密钥**：`WEREAD_API_KEY` 存服务器 `.env`，与票据 07 同管理原则，不入库；
4. **边界**：只拉自己的划线/想法，**绝不拉取书籍全文**（封号潮的红线是"爬书传播"）；不做书架管理、不做阅读进度；官方条款若调整频率限制，退化为每周一次（周复盘时段）。
