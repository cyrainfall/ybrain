# 08 决策：MVP 捕获入口范围与协议

Type: grilling
Status: claimed
Blocked by: 05, 06

## Question

基于渠道调研（05）与架构决策（06），与本人对话确定 MVP 捕获层的设计：

1. **渠道范围**：网页剪藏、Android 速记、微信内容三条渠道各自做到什么程度（哪些首发、哪些降级方案）；
2. **捕获接口协议**：接收服务的接口形态（路径、鉴权方式——长令牌如何在书签工具和 Android 工具里配置）、请求字段（原文/链接/标题/来源渠道/时间）；
3. **收件箱模型**：捕获内容先进"收件箱"（Inbox）等待提炼，还是捕获即触发提炼；"稍后读"队列如何体现；
4. **正文提取位置**：浏览器端提取正文发送，还是服务器只收网址自行抓取（影响微信文章等需登录页面的处理）；
5. **失败处理**：网络失败、提取失败时内容如何不丢失（客户端重试/手动补录）。

产出：捕获层决策记录 + 接口约定（后续自研捕获服务的依据）。

## Answer

2026-09-06 与本人对话定稿。完整接口约定见工件 [prototypes/capture-api.md](../prototypes/capture-api.md)。

1. **渠道范围**：MVP = 自研浏览器扩展（Mac，端内 Readability 提取正文）+ HTTP Shortcuts（Android，分享菜单发 URL/文本，零代码）；**企业微信自建应用不进 MVP**（公众号走"浏览器打开→分享 URL→服务器抓公开链接"降级；文字灵感复制后发纯文本；通知/周报推送暂靠打开 Web 界面，雾区跟踪）；**微信读书同步不进 MVP**（票据 15 定稿：MVP 后第一个增量，每日增量拉取）；
2. **接口协议**：`POST /capture`（ybrain 进程内 Bun.serve，端口 8787，仅 Tailscale 网卡）；Bearer 令牌鉴权，**按渠道独立三个令牌**（web/android/weread，.env 管理、可单独吊销）；字段 source/type/title/url/author/body/created；
3. **收件箱模型**：捕获永远先落盘 `0-Inbox/`（status: inbox）再返回 200，提炼异步走票据 12 队列；"稍后读"即收件箱本身，不另建队列；
4. **正文提取**：双路——扩展端内提取为主（最准，覆盖需 JS/登录页）；Android 仅给 URL 时服务器抓取（Readability 类提取，公众号公开链接可抓）；抓取失败落盘"仅链接"笔记并标记 `fetch_failed`，不丢内容、可重试；
5. **失败处理**：扩展失败存 chrome.storage 本地队列自动重发（角标提示积压数）；Shortcuts 内置 2 次重试 + 失败通知手动重发；服务器任何情况下先落盘再谈处理。
